# Задачи по оптимизации Labirit

16 задач для самостоятельной реализации командой. Основаны на текущем коде проекта; указанные эффекты — цели, которые нужно подтвердить измерениями. Здесь N = rows × columns, E — число открытых рёбер, W — число шагов случайных блужданий.

Общие критерии: проверять связность, согласованность стен соседей, закрытые внешние границы генераторов и отсутствие циклов у генераторов дерева (N − 1 ребро). Дополнить существующие проверки случаями 1×1, 1×N, N×1, прямоугольниками и несколькими seed. Сравнивать время и пиковую память на одинаковых входах и сборках. Если меняется порядок случайных выборов или их распределение, явно документировать это и сравнивать характеристики лабиринтов; совпадение seed само по себе не гарантирует совпадение результата между версиями.

## 01. Прим: заменить списки посещённых клеток и границы

- **Где:** `backend/prim.c`, функции `in_visited`, `add_visit`, `add_bind`, `pop_bind`.
- **Проблема:** проверка посещения линейна по длине списка; каждое ребро требует отдельного выделения памяти. Повторная обработка уже посещённой цели снова добавляет её соседей в границу.
- **Что сделать:** хранить посещение в массиве по индексу клетки, границу — в динамическом массиве; удалять выбранное ребро заменой последним. Для уже посещённой цели сразу завершать обработку ребра; добавлять соседей только при первом посещении клетки. Исправить начальное добавление рёбер с учётом размеров 1×N и N×1.
- **Цель:** O(1) проверка посещения и удаление из границы; O(N) обработка на решётке с ограниченной степенью, O(N) память.
- **Готово, когда:** число добавленных рёбер линейно по N, нет выделения памяти на каждое ребро, выполнены общие проверки. Отдельно оценено изменение топологии: текущий `pop_bind` выбирает с геометрическим смещением к началу списка, а равномерный выбор из массива меняет распределение.

## 02. Growing tree: убрать линейный поиск самой новой активной клетки

- **Где:** `backend/growing_tree_alg.c`, сканирование `active_age`.
- **Проблема:** в 60% итераций просматривается весь активный массив; суммарные затраты могут быть O(N²).
- **Что сделать:** сочетать плотный массив для случайного выбора с порядком добавления активных клеток. Например, хранить двусвязные связи по индексам клеток и позицию каждой клетки в массиве: новая клетка добавляется в конец порядка, любая удаляется за O(1).
- **Цель:** выбор самой новой или случайной клетки и удаление за O(1); вся генерация за O(N).
- **Готово, когда:** сохранена политика 60% newest / 40% random, удаление последнего и произвольного элемента корректно, нет сканирования активного набора, измерена зависимость времени от N.

## 03. Уотсон: выбирать непосещённую клетку без обходов сетки

- **Где:** `backend/watson_alg.c`, `watson_has_unvisited`, `watson_take_random_unvisited`.
- **Проблема:** перед очередным блужданием сетка обходится для проверки завершения, подсчёта и выбора непосещённой клетки.
- **Что сделать:** завести плотный массив непосещённых индексов, обратный массив позиций и счётчик. При включении клетки в дерево удалять её заменой последним элементом; выбирать старт равномерно из оставшихся.
- **Цель:** проверка завершения и выбор старта за O(1), суммарная поддержка набора за O(N), вместо повторных O(N) сканирований.
- **Готово, когда:** каждая клетка удаляется ровно один раз, старт всегда вне дерева, выбор равномерен. Измерены затраты обслуживания набора отдельно от W; линейное время всей генерации не обещается, поскольку случайные блуждания остаются.

## 04. Уотсон: индексировать позиции клеток в текущем пути

- **Где:** `backend/watson_alg.c`, ветка `WATSON_IN_WALK` и обрезка `path`.
- **Проблема:** при обнаружении петли её начало ищется обратным проходом с повторным преобразованием индексов в координаты.
- **Что сделать:** хранить `path_position[cell]` с признаком отсутствия. Получать позицию начала петли за O(1), обрезать хвост и сбрасывать позиции удалённых клеток. Разделить компактные признаки принадлежности дереву и пути вместо использования массива `Cell **state`.
- **Цель:** O(1) нахождение начала петли, O(k) очистка удаляемого хвоста, O(N + W) обслуживание пути. Текущая очистка хвостов уже амортизируется по шагам блуждания, поэтому не заявлять устранение квадратичной сложности без доказательства.
- **Готово, когда:** проверены короткие, вложенные и повторные петли, нет устаревших позиций, измерено время на шаг блуждания и потребление памяти.

## 05. Ввести быстрый генератор случайных чисел с локальным состоянием

- **Где:** `backend/table_init.c`, все генераторы с `rand()`/`srand()`.
- **Проблема:** `init_table` сбрасывает общий PRNG, генераторы используют глобальное состояние; это мешает воспроизводимой параллельной работе и может добавлять затраты синхронизации библиотеки.
- **Что сделать:** выбрать PRNG с явным состоянием на экземпляр генерации, определить преобразование seed и API выбора числа в диапазоне без смещения от `%`. Предусмотреть получение пакетов случайных битов для двоичного дерева.
- **Готово, когда:** одинаковые входы воспроизводимы независимо от порядка запусков и количества потоков, проверены диапазоны и частоты выбора, измерены скорость PRNG и время генераторов. Изменение результатов относительно `rand()` документировано.

## 06. Распараллелить подсчёт бенчмарков

- **Где:** `analisys/combined_benchmarks.c`, `analisys/benchmarks_main.c`, `backend/prim.c`, `backend/metrics.c`, `deter.h`, `Makefile`.
- **Зависимость:** задача 05; списки Прима и метрики должны принадлежать конкретному запуску либо потоку.
- **Что сделать:** добавить ограниченный пул потоков и параметр числа workers. Распределять независимые случаи `(алгоритм, размер, seed)`; хранить отчёты по заранее назначенным индексам, записывать JSON одним потоком в стабильном порядке. Прогресс обновлять централизованно. Ограничивать одновременные задания с учётом их памяти.
- **Цель:** сократить полное время расчёта набора, измерив ускорение на 1, 2, 4 и доступном числе ядер.
- **Готово, когда:** отсутствуют гонки, топологические результаты совпадают с последовательным запуском, ошибки workers корректно завершают прогон. Для сравнения времени отдельного генератора сохранён последовательный режим: конкуренция за CPU и память влияет на параллельные измерения.

## 07. Исследовать SIMD для двоичного дерева

- **Где:** `backend/binary_tree_alg.c`, представление стен в `deter.h`, `Makefile`.
- **Зависимость:** задача 05; задача 08 может упростить загрузки и записи.
- **Что сделать:** сначала подготовить скалярную обработку внутренних клеток с пакетами случайных битов и отдельной обработкой границ. Затем сделать экспериментальный SIMD-вариант, например AVX2 для x86, с определением поддержки CPU и скалярным fallback. Формировать маски стен через явные байтовые операции: раскладку C bit-fields нельзя считать переносимым SIMD-контрактом. Учесть записи ответных стен соседей и хвост строки.
- **Цель:** повысить число обрабатываемых клеток в секунду; асимптотика остаётся O(N).
- **Готово, когда:** SIMD и скалярный вариант дают одинаковые стены на одном потоке случайных решений, проверены ширины вокруг границы SIMD-блока и вырожденные размеры. Измерено полное время с PRNG; если выигрыша нет, оформлен результат эксперимента с причинами.

## 08. Сделать хранение сетки непрерывным

- **Где:** `backend/table_init.c`, `clear_table`, `deter.h`.
- **Проблема:** каждая строка выделяется отдельно, что увеличивает число аллокаций и фрагментацию.
- **Что сделать:** выделять единый блок клеток; при необходимости оставить массив указателей на строки для совместимости. Инициализировать байты пакетно, определить владение памятью и обновить её учёт. Проверять переполнение размеров до выделения.
- **Цель:** постоянное число аллокаций на сетку, лучшая локальность доступа.
- **Готово, когда:** корректны освобождение и обработка отказа выделения, учтены все байты, сравниваются время инициализации, пиковая память и время обходов на крупных сетках.

## 09. Снизить постоянные затраты DFS

- **Где:** `backend/dfs_algorithm.c`.
- **Проблема:** при возврате к клетке повторно собираются соседи и вычисляются координаты через деление и остаток.
- **Что сделать:** оценить хранение в кадре стека оставшихся направлений или маски непроверенных соседей; передавать направление выбранного перехода для удаления стен без повторного вычисления координат. Сравнить с компактным текущим стеком индексов.
- **Цель:** ускорить текущий O(N) алгоритм при контролируемом увеличении размера кадра.
- **Готово, когда:** измерены операции на клетку, время и максимальная память стека. Если используется заранее перемешанный порядок направлений, проверены и документированы изменения случайного выбора и топологии.

## 10. Убрать лишнюю подготовку рекурсивного разделения

- **Где:** `backend/recursive_division_algorithm.c`, `backend/table_init.c`.
- **Проблема:** сетка сначала заполняется закрытыми стенами, затем `open_all_internal_walls` открывает внутренние стены, записывая обе стороны каждого ребра.
- **Что сделать:** добавить вариант инициализации сразу с открытыми внутренними стенами и закрытым периметром. Для разделяющих стен рассмотреть два диапазона по сторонам прохода вместо проверки прохода на каждой клетке. Оценить явный стек областей для контроля глубины рекурсии.
- **Цель:** уменьшить число проходов и записей; не заявлять улучшение асимптотики без анализа.
- **Готово, когда:** отдельно измерены инициализация и разделение, проверены длинные узкие сетки, границы и глубина/память стека; изменение порядка рекурсивной обработки не нарушает договорённость о seed.

## 11. Уменьшить влияние инструментирования на время генерации

- **Где:** `deter.h`, `backend/metrics.c`, вызовы `labirit_metrics_*`, `analisys/combined_benchmarks.c`.
- **Проблема:** измеряемые циклы постоянно обновляют общий счётчик шагов; полученное время включает инструментирование.
- **Что сделать:** добавить режим сборки без счётчиков и отдельный режим подсчёта шагов/памяти; где возможно, накапливать шаги локально и обновлять счётчики пакетно. Метрики хранить в контексте запуска для задачи 06.
- **Готово, когда:** JSON явно различает режимы, время берётся из запуска без инструментирования, счётчики — из отдельного воспроизводимого запуска. Проверены баланс выделений/освобождений и совпадение прежних значений шагов при сохранённом определении шага.

## 12. Вычислять самый длинный путь дерева через диаметр

- **Где:** `analisys/combined_benchmarks.c`, `find_longest_path`, `dfs_longest`, `bfs_farthest`.
- **Проблема:** DFS запускается из каждой клетки; на дереве это O(N²), а на графе с циклами перебор простых путей может быть экспоненциальным. Диаметр уже вычисляется отдельно.
- **Что сделать:** после проверки связности и E = N − 1 использовать уже вычисленный диаметр как длину самого длинного пути в рёбрах. Для циклических графов задать ограниченный точный режим или явно помеченный недоступный результат; два BFS не гарантируют точный диаметр общего графа.
- **Цель:** O(N) расчёт для дерева без рекурсивного перебора.
- **Готово, когда:** результаты совпадают со старым перебором на малых деревьях, определена семантика для 1×1, лесов и циклов, крупные деревья обрабатываются без риска переполнения рекурсивного стека.

## 13. Ускорить ASPL и энтропию расстояний

- **Где:** `analisys/combined_benchmarks.c`, `compute_aspl_slow`, `compute_distance_entropy_slow`; аналогичный код в `analisys/topology_benchmarks.c`.
- **Проблема:** два отдельных набора BFS из всех клеток повторяют работу и выделяют очередь/расстояния для каждого старта.
- **Что сделать:** объединить накопление суммы расстояний и гистограммы в одном наборе BFS, переиспользовать буферы. Для дерева реализовать точный ASPL через размеры поддеревьев: сумма расстояний по неупорядоченным парам равна сумме `s × (N − s)` по рёбрам, среднее — эта сумма, делённая на `N × (N − 1) / 2`. Для крупных сеток предусмотреть отдельный режим оценки по выборке стартов с явным указанием выборки; энтропия из выборки является оценкой.
- **Цель:** точный ASPL дерева за O(N); точные ASPL и энтропия общего графа одним набором обходов за O(N(N + E)), O(N) рабочая память.
- **Готово, когда:** точные результаты совпадают с исходными на малых сетках, промежуточные произведения не переполняются, режимы оценки и точного расчёта различаются в отчёте. Общая реализация исключает расхождение дублированных версий.

## 14. Ускорить box counting для фрактальной размерности

- **Где:** `analisys/combined_benchmarks.c`, `wall_point_occupied`, `count_wall_boxes`, `compute_fractal_dimension`.
- **Проблема:** для каждого масштаба заново вычисляется занятость точек стен, включая рекурсивные проверки узлов.
- **Что сделать:** один раз построить карту занятости с текущей семантикой и иерархию блоков 2×2 через логическое OR. На каждом уровне подсчитывать занятые блоки, корректно обрабатывая неполные блоки справа и снизу.
- **Цель:** заменить повторную работу порядка O(N log D) на построение иерархии за O(N), где D — максимальный линейный размер карты; оценить дополнительную память.
- **Готово, когда:** количество блоков на каждом масштабе совпадает с исходным, итоговая размерность совпадает в пределах погрешности, проверены нечётные размеры, прямоугольники и внешняя граница.

## 15. Подготовить оптимизированную сборку и надёжные замеры

- **Где:** `Makefile`, `analisys/combined_benchmarks.c`, `analisys/benchmarks_main.c`, формат результатов.
- **Проблема:** текущие флаги не задают оптимизацию, время округляется до микросекунд, на seed выполняется один замер.
- **Что сделать:** добавить отдельные debug/release/performance цели; сравнить `-O2`, `-O3` и LTO, а аппаратные флаги оставить явной локальной опцией. Добавить прогрев, повторы на заново подготовленных одинаковых входах, замеры в наносекундах и сводку медианы/разброса. Записывать компилятор, флаги, режим метрик и число workers; раздельно учитывать генерацию, инициализацию, анализ и полное время.
- **Готово, когда:** все варианты проходят проверки корректности, короткие генерации измеряются с достаточной длительностью, выбранная конфигурация подтверждена сравнением. Прогоны производительности не перезаписывают эталонные JSON без явно выбранного пути вывода.

## 16. Сократить затраты вывода лабиринтов и прогресса

- **Где:** `frontend/graph.c`, `print_maze`; `analisys/combined_benchmarks.c`, `write_ascii_lines`, `print_progress`.
- **Проблема:** вывод использует множество `printf`/`fputc`, прогресс делает `fflush` после каждого случая.
- **Что сделать:** собирать строку лабиринта в переиспользуемый буфер и выводить её одним вызовом; аналогично записывать ASCII-строки примеров. Обновлять прогресс по временному интервалу и дать возможность его отключить. Централизовать вывод для многопоточного режима.
- **Цель:** уменьшить число вызовов функций вывода и принудительных сбросов буфера.
- **Готово, когда:** текстовое представление и JSON совпадают с прежними, ошибки записи обрабатываются, сравниваются время вывода в файл и терминал и полное время набора мелких бенчмарков.

## Рекомендуемый порядок

Сначала 15 и 11 для достоверной базы измерений; затем 01–04 и 12–13 как основные алгоритмические улучшения. Задачи 05 и 08 подготовят основу для 06 и 07. Задачи 09, 10, 14 и 16 выполнять по результатам профилирования. Каждую оптимизацию измерять отдельно, прежде чем объединять изменения.
