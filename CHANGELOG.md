# Changelog

## [Unreleased]

Изменения бенчмарка реализованы в ветке `perf/benchmark-optimization`.
Эта запись документирует результат; слияние кода в `docs/tasks` не выполнялось.

### Added

- Параллельный расчёт независимых метрик через POSIX Threads. Каждый работник использует собственный контекст результата и временные буферы, читая общую неизменяемую таблицу.
- Ожидание работников через `pthread_join()` и синхронное выполнение задачи при отказе `pthread_create()`.
- Шесть дочерних процессов через `fork()`, по одному на алгоритм, с отдельными JSON и изолированными RNG и метриками. Контроль завершения и ошибок через `waitpid()`.
- Прогресс по каждому алгоритму: завершённые прогоны, процент, прошедшее время, последний размер и seed. Вывод каждые 10 прогонов и после последнего.
- Флаг сборки `-pthread` и тесты потокового анализа, включая отказ создания работников.

### Changed

- Для связного дерева с N − 1 ребром `longest_path` берётся из уже рассчитанного диаметра. Повторный перебор путей исключён; схема JSON сохранена.
- Каталоги готовит родитель, примеры лабиринтов записываются один раз после успешного завершения всех алгоритмов.

### Validation

- Сборка и 150 тестов генераторов прошли; потоковые метрики сверены с последовательными, включая дерево, цикл, несвязный граф и 1×1. ThreadSanitizer не обнаружил гонок в проверенных случаях.
- В коротком многопроцессном сравнении проверены 24 прогона и обработка ошибки ребёнка.
- При сравнении 2280 новых и резервных записей все поля кроме времени генерации совпали точно. Нет пропусков, дублей или изменений порядка; шесть примеров совпали.
- Пользовательский замер полного запуска: 610,18 с реального времени, 96,04 мин пользовательского CPU-времени. Контролируемое сравнение отдельных оптимизаций ещё не выполнено.

### Known limitations

- Число процессов фиксировано; ограниченного пула заданий и CLI-параметра workers нет.
- ASPL и энтропия пока повторяют наборы BFS независимо.
- Для циклических графов сохранён дорогой перебор самого длинного пути; двойной BFS не гарантирует точного диаметра.
- Поле `microseconds` измеряет прошедшее время только генерации и включает влияние конкурентной нагрузки. При сравнении с резервными данными время отдельных генераций выросло, хотя полный набор выполняется параллельно.
