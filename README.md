# Labirit

Генератор лабиринтов на C для Linux. Поддерживает алгоритмы Прима, DFS, растущего дерева, Уотсона, двоичного дерева и рекурсивного разделения.

Нужны GNU Make и компилятор C с поддержкой C23.

## Запуск

```bash
make
```

Команда собирает программу и выводит лабиринт 10×10. Чтобы выбрать алгоритм, размер и seed, сначала соберите программу, затем запустите её с аргументами:

```bash
make compile
./main dfs 20 12 42
```

Формат: `./main [алгоритм] [столбцы] [строки] [seed]`. Если seed не задан, он выбирается случайно. Для списка аргументов используйте `./main --help`.

## Другие команды

```bash
make benchmark  # запустить бенчмарки; JSON-файлы результатов перезаписываются
make test       # собрать и запустить тесты
make clean      # удалить собранные программы
```



# УНИКАЛЬНАЯ ИНФОРМАЦИЯ О ВЕТКЕ

## Суть проблемы

Первоначально ASPL и энтропия считались отдельно, так как результат разный и по смыслу сильно разниться. Внутри оба имеют реализацию через BFS обход деревьев, и до определенного момента им нужна одна и та же высчитываемая информация, с разницей только, что ASPL суммирует и ищет долю, а энтропия основана на подсчёте частоты встречаниия. Поэтому было решено написать один сложный, но обьединяющий обе логики алгоритм.

## Компромиссы

Во первых было замечено место, в которое можно внедрить SIMD. Хоть скорее всего на -O3 данная оптимизация была реализуется самостоятельно, но на уровне обычного запуска такого нет. На основе поддерживаемости 256 битных инструкций было ускорено место заполнения dist. Общий прирост скорости на этом месте для полного бенчмарка составил 20 секунд.
Так же после обьединения функций было замечено, что количество потоков для каждого процесса бенчмарка стало не 3, а 2. Это привело к тому, что вместо 70-80% ресурсов процессора полный бенчмарк стал потреблять примерно 45-50% ресурсов, что привело к уменьшению количества времени работы на cpu. Так как обьединенная функция подсчёта дистанций является для бенчмарка явно самой долгой и сложной функцией было решено, что оправдано перераспределение свободного cpu в работу функции compute_distance_metrics, которая выдаёт ASPL и энтропию.

## Детали реализации

Внутри compute_distance_metrics считается bfs для каждой клетки, поэтому общая сложность для подобного графа это O(N**2). Каждая клетка считается независимо(только лабиринт общий для чтения), поэтому это даёт возможность простой реализации многопоточности для подсчёта метрик. Было реализовано решение по созданию отдельных потоков. Их количество определяется define, так как хоть чем больше потоком, тем лучше по времени, но относительно характеристики занимаемого времени на cpu увеличение количества потоков не оправдано на значениях больше 2, так как на 2 потоков идёт использование 70-80%cpu, а если больше ставить, будет под 100%. утилита time на момент реализации таски даёт такой вывод:
Executed in  331.17 secs    fish           external
   usr time   45.19 mins    0.21 millis   45.19 mins
   sys time    0.01 mins    1.10 millis    0.01 mins

при условии что на 10 потоков было 280 секунд работы на usr time в 53 минуты, и создаётся на cpu разный уровень нагрузки, то для данной реализации оправдано ожидание на доп 40 сек.
