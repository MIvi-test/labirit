# Labirit

Генератор лабиринтов на C для Linux. Поддерживает алгоритмы Прима, DFS, растущего дерева, Уотсона, двоичного дерева и рекурсивного разделения.

Нужны GNU Make и компилятор C с поддержкой C23.

## Запуск

```bash
make
```

Команда собирает программу и выводит лабиринт 10×10. Чтобы выбрать алгоритм, размер и seed, сначала соберите программу, затем запустите её с аргументами:

```bash
make compile
./main dfs 20 12 42
```

Формат: `./main [алгоритм] [столбцы] [строки] [seed]`. Если seed не задан, он выбирается случайно. Для списка аргументов используйте `./main --help`.

## Другие команды

```bash
make benchmark  # запустить бенчмарки; JSON-файлы результатов перезаписываются
make test       # собрать и запустить тесты
make clean      # удалить собранные программы
```

# Уникальная информация

Данная оптимизация была придумана при анализе двоичного дерева. Функция rand() хоть и не является рекомендуемой для криптографии, но всё равно имеет вычислительную нагрузку, в рамках двоичного дерева именно rand являлся ключевым замедляющим элементом. Поэтому Было решено внедрить более простую функцию генерации псевдослучайных чисел. 

## Суть проблемы

Очевидно, что деление по остатку не использует весь диапазон псевдослучайных битов(30 битов откидывались) + важно отметить, что в рамках задачи принимает, что они имеют равную случайность и энтропию и на основе этого была придумана идея с буфферами.

## Детали реализации

алгоритм SplitMax64 известен тем, что он есть в java и его активно используют, его свойства и методы разработки явно подходят под эту задачу, поэтому он интегрирован.
Методом интеграции является ld_preload, что даёт очень высокое удобство для тестирования и сравнения. Но из-за этого это работает только на линуксе.

## Результаты тестов

на локальных тестах через было выяснено, что общее ускорение от буферов + splitmax64 дали выигрыш в скорости примерно в 2 раза. Так же, благодаря preload, было подсчитано, что функция rand вызывалась раньше 65025, а после буфферов 2098(сетка 256х256).
